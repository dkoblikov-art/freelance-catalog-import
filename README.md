# CAT-001 — импорт товаров из CSV

Консольная утилита проверяет CSV и сохраняет корректные товары в PostgreSQL
одной транзакцией. Новый SKU создаёт товар; существующий SKU обновляет имя,
цену и остаток через UPSERT. Ошибочные строки получают причины отклонения.

## Технологии и требования

- Python 3.14 или новее; проверенная версия — 3.14.4.
- PostgreSQL 17 (`postgres:17-alpine`) в Docker Compose; Docker Desktop
  с Linux containers и Compose v2 с поддержкой `up --wait`.
- psycopg 3 с binary extra и pytest; проверенные версии — 3.3.4 и 9.1.1.
- Git; PowerShell для команд ниже. В PyCharm выберите интерпретатор из `.venv`.

Команды выполняются из корня проекта. При ошибке остановитесь перед следующим
шагом. Для первой установки нужен доступ к пакетному индексу Python и Docker
registry; локальный порт `55433` должен быть свободен.

## Установка Python-окружения

На новом компьютере получите копию проекта, откройте его корень в PowerShell
и создайте виртуальное окружение:

```powershell
py -3.14 -m venv .venv
./.venv/Scripts/python.exe -m pip install "psycopg[binary]==3.3.4" "pytest==9.1.1"
```

Если в существующей `.venv` отсутствует pip, используйте уже установленный `uv`:

```powershell
uv pip install --python .venv/Scripts/python.exe "psycopg[binary]==3.3.4" "pytest==9.1.1"
```

Диапазоны совместимых версий заданы в `pyproject.toml`. Запуск идёт из исходников
через `python -m catalog_import`; установка самого проекта как пакета не требуется.

## PostgreSQL через Docker Compose

Создайте `.env` из шаблона, только если файл ещё не существует:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

В `.env` оставьте `POSTGRES_USER=cat001_local`, `POSTGRES_DB=cat001_learning`
и задайте собственный непустой `POSTGRES_PASSWORD`. Для буквальных `$` и `#`
заключите пароль в одинарные кавычки; тогда сам пароль не должен содержать
одинарную кавычку. Шаблон содержит пустые поля паролей, а `.env` исключён из Git.
Переменные `POSTGRES_*` текущего процесса имеют приоритет над `.env`.

```powershell
docker compose --env-file .env -p cat001 config --quiet
docker compose --env-file .env -p cat001 up -d --wait db
docker compose --env-file .env -p cat001 ps
```

Ожидается сервис `db` в состоянии `healthy`, контейнер `cat001-db-1` и порт
`127.0.0.1:55433`. `config --quiet` проверяет конфигурацию без печати паролей;
обычный `config` без этого параметра может раскрыть секреты.

При первом запуске с пустым volume создаются роль `cat001_local` и БД
`cat001_learning`. Данные находятся в именованном volume `cat001_postgres_data`
вне репозитория. Изменение `POSTGRES_*` после инициализации volume не меняет
существующие роли, пароли или БД. Healthcheck проверяет готовность сервера,
но не проверяет пароль или наличие таблицы.

### Первоначальное создание таблицы и тестовой БД

Следующие команды предназначены для **нового окружения**. На уже настроенной
БД повторять создание таблицы и тестовой БД не нужно. Существующие таблицы
не удаляйте. Проверки для существующего контейнера приведены в
[инструкции интеграции](docs/POSTGRES_INTEGRATION.md).

Таблица создаётся одной транзакцией с остановкой при SQL-ошибке:

```powershell
$schema = Get-Content -LiteralPath sql/001_products.sql -Raw -Encoding UTF8
("SET LOCAL search_path = public, pg_catalog;" + [Environment]::NewLine + $schema) |
    docker compose --env-file .env -p cat001 exec -T db psql -X -U cat001_local -d cat001_learning --single-transaction -v ON_ERROR_STOP=1
if ($LASTEXITCODE -ne 0) { throw 'Schema creation failed; stop.' }

docker compose --env-file .env -p cat001 exec -T db psql -X -U cat001_local -d cat001_learning -v ON_ERROR_STOP=1 -c 'CREATE DATABASE cat001_test OWNER cat001_local TEMPLATE template0;'
if ($LASTEXITCODE -ne 0) { throw 'Test database creation failed; stop.' }
```

SQL-файлы не применяются автоматически. `sql/000_create_databases.sql` в этой
последовательности не запускайте: он создаёт обе БД, а учебная БД уже создана
образом. Для модульных тестов PostgreSQL и тестовая БД не требуются.

## Подключение и импорт

Python не загружает `.env` автоматически. Для приложения задайте отдельно:

```text
PGHOST=127.0.0.1
PGPORT=55433
PGDATABASE=cat001_learning
PGUSER=cat001_local
PGPASSWORD=<пароль роли cat001_local из локального .env>
```

В PyCharm создайте личную Run Configuration: Python из `.venv`, Module name
`catalog_import`, рабочий каталог — корень проекта, Parameters — путь к CSV.
Задайте переменные выше в Environment variables и отключите **Store as project file**.

В PowerShell можно задать подключение с вводом пароля без записи в историю:

```powershell
$env:PGHOST = '127.0.0.1'
$env:PGPORT = '55433'
$env:PGDATABASE = 'cat001_learning'
$env:PGUSER = 'cat001_local'
$cat001Password = Read-Host 'Password for cat001_local' -AsSecureString
try {
    $env:PGPASSWORD = [System.Net.NetworkCredential]::new('', $cat001Password).Password
}
finally {
    $cat001Password.Dispose()
    $cat001Password = $null
}

./.venv/Scripts/python.exe -m catalog_import tests/fixtures/products.csv
```

Для чистой таблицы ожидается отчёт:

```text
Всего строк: 2
Сохранено: 2
Отклонено: 0
```

Проверка UPSERT на демонстрационных данных:

```powershell
./.venv/Scripts/python.exe -m catalog_import tests/fixtures/products_update.csv
```

Ожидается одна сохранённая строка; `DEMO-001` получает имя
`Учебный товар обновлён`, цену `19.90`, остаток `8`. Общее количество товаров
после этих двух импортов в первоначально пустую таблицу остаётся равным двум.
В SQL-консоли подключения к `cat001_learning` проверьте:

```sql
SELECT sku, name, price, stock FROM public.products ORDER BY sku;
SELECT count(*) FROM public.products;
```

Повторный импорт исходного `products.csv` вернёт исходные значения `DEMO-001`.
После работы в PowerShell удалите пароль из окружения текущего процесса:

```powershell
Remove-Item Env:/PGPASSWORD -ErrorAction SilentlyContinue
```

CLI разрешает запись только в `cat001_learning`, проверяя и настройки,
и фактическое имя БД. Пароли и строки подключения не передаются аргументами CLI;
сообщения драйвера скрыты, чтобы не раскрывать данные подключения и строки CSV.

## Правила валидации CSV

```csv
sku,name,price,stock
DEMO-001,Учебный товар,12.50,3
DEMO-002,"Товар, с запятой",0.01,0
```

- Кодировка UTF-8, BOM допустим; разделитель — запятая. Кавычки и переносы
  внутри заключённых в кавычки полей поддерживаются стандартным `csv`.
- Заголовок содержит ровно `sku`, `name`, `price`, `stock`, без повторений
  и внешних пробелов; порядок колонок может отличаться.
- Пустой файл, пустая строка, неверное количество полей, ошибка CSV или
  кодировки отменяют весь импорт до подключения к БД. Файл только с заголовком
  допустим и даёт нулевой отчёт.
- Все значения обязательны; внешние пробелы удаляются, нулевой символ запрещён.
- SKU чувствителен к регистру. Первая корректная строка резервирует SKU;
  последующие корректные строки с этим SKU отклоняются как дубликаты.
  Невалидные строки не резервируют SKU и получают собственные причины ошибок.
- Цена — обычная десятичная запись с точкой, начальный `+` допустим;
  диапазон `0.01..9999999999.99`, не более двух знаков после точки.
  `1.230`, `1e2`, `1_000`, `NaN`, `Infinity` отклоняются.
  Используется `Decimal`, без округления и преобразования через `float`.
- Остаток — цифры `0–9`, диапазон `0..2147483647`, ведущие нули допустимы.
  Знаки, дроби, экспоненты и разделители разрядов запрещены.
- Проверенные строки и ошибки хранятся в памяти: файл должен помещаться
  в оперативную память. Потоковая загрузка не реализована.

## UPSERT, транзакция и отчёт

Весь файл проверяется до подключения к БД. Ошибки значений отдельных строк
не мешают сохранению остальных. Если корректных строк нет, подключения не будет.

Все корректные товары сохраняются параметризованным
`INSERT ... ON CONFLICT (sku) DO UPDATE`: обновляются имя, цена и остаток.
Одна транзакция охватывает весь набор; SQL-ошибка откатывает и вставки,
и обновления. Повторный импорт не создаёт второй товар с тем же SKU.

Отчёт содержит количество строк данных без заголовка, сохранённых и отклонённых
строк, номера и все причины отклонения. Одна строка с несколькими ошибками
считается отклонённой один раз. Номер — физическая строка начала CSV-записи.
Сохранённые включают вставки и обновления.

При ошибке настройки или БД отчёт указывает ноль подтверждённо сохранённых;
валидные строки не объявляются отклонёнными. При потере связи во время COMMIT
результат может быть неизвестен: проверьте БД перед повторным запуском.

Коды завершения: `0` — успешный импорт без отклонений; `1` — импорт завершён
с отклонёнными строками; `2` — ошибка файла, настройки или БД.

## Тесты

Модульные тесты не подключаются к PostgreSQL:

```powershell
./.venv/Scripts/python.exe -m pytest -m "not integration" -q -p no:cacheprovider --basetemp=./.pytest_tmp_cat001_unit
```

`--basetemp` должен указывать на отдельный доступный каталог только для pytest:
pytest очищает его при запуске. Каталоги `.pytest_tmp*/` исключены из Git.
Если старый каталог недоступен по правам, задайте новое имя, например
`.pytest_tmp_cat001_unit_2`. `-p no:cacheprovider` отключает необязательный кэш.

Интеграционные тесты включаются явно и используют только отдельную БД
`cat001_test`. В личной конфигурации PyCharm задайте:

```text
CAT001_RUN_PG_TESTS=1
CAT001_TEST_HOST=127.0.0.1
CAT001_TEST_PORT=55433
CAT001_TEST_DBNAME=cat001_test
CAT001_TEST_USER=cat001_local
CAT001_TEST_PASSWORD=<пароль роли cat001_local>
```

```powershell
./.venv/Scripts/python.exe -m pytest -m integration -q -p no:cacheprovider --basetemp=./.pytest_tmp_cat001_integration
```

Тесты не берут настройки из рабочих `PG*`. При включённом режиме неверное имя БД,
неполные настройки или недоступное подключение приводят к ошибке теста.
Роль должна иметь право подключения и создания временных таблиц в `cat001_test`.
До создания таблицы проверяется фактическое имя БД; `search_path=pg_temp,pg_catalog`
исключает обращение к постоянной `public.products`. Временные таблицы исчезают
после закрытия соединения, существующие данные не очищаются.

Обычный `python -m pytest -q` пропускает интеграционные тесты, пока
`CAT001_RUN_PG_TESTS` не равно `1`. Для ввода тестового пароля из PowerShell
и дополнительных проверок используйте [инструкцию интеграции](docs/POSTGRES_INTEGRATION.md).

Подтверждённая пользователем проверка CAT-001: 91 модульный и 7 интеграционных
тестов пройдены; реальный импорт и UPSERT выполнены, после обновления `DEMO-001`
в таблице осталось два товара.

## Структура и локальные данные

- `catalog_import/importer.py` — модели, валидация и чтение CSV.
- `catalog_import/db.py` — настройки подключения и транзакционный UPSERT.
- `catalog_import/__main__.py` — CLI и отчёт.
- `sql/001_products.sql` — схема таблицы для первоначальной подготовки.
- `tests/` — модульные и интеграционные тесты; `fixtures/` — вымышленные данные.
- `.env.example` — шаблон настроек без паролей.
- `.gitignore` исключает `.env`, `.venv`, `.idea`, `__pycache__`, кэши,
  временные файлы pytest и `data/` для локальных CSV поставщика.
  Данные PostgreSQL хранятся в Docker volume вне рабочего дерева Git.

Тег образа `postgres:17-alpine` обновляется в пределах PostgreSQL 17;
точная версия образа не закреплена. Python-зависимости в командах установки
закреплены на проверенных версиях.
